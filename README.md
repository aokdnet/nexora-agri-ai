# NEXORA AGRI AI — WebApp (Phase 1)

> ผู้ช่วยเกษตรกร ตั้งแต่ดินจนถึงตลาด

โครง WebApp/PWA ที่แปลงมาจาก mockup สามหน้า — Command Center, หน้าจอมือถือเกษตรกร และ Plant Doctor flow

## สั่งรัน

```bash
npm install
npm run dev
```

เปิด http://localhost:3000

> ต้องมี Node.js 20 ขึ้นไป (Next.js 15 ไม่รองรับ Node 18 แล้ว)

## เส้นทางในแอป

| URL | ใคร | ตอบคำถามอะไร |
| --- | --- | --- |
| `/` | เกษตรกรที่อยู่ในแปลง | วันนี้ต้องทำอะไร |
| `/plots` | เกษตรกร | แปลงไหนมีปัญหา |
| `/plots/[id]` | เกษตรกร | แปลงนี้เป็นยังไง + AI แนะนำอะไร |
| `/scan` → `/scan/result` | เกษตรกร | ใบเป็นแบบนี้เกิดจากอะไร |
| `/ask` | เกษตรกร | ถามด้วยเสียง (ยังไม่ต่อโมเดล) |
| `/money` | เกษตรกร | ฤดูนี้กำไรต่อไร่เท่าไร |
| `/dashboard` | เจ้าของฟาร์ม / สหกรณ์ | ทั้งฟาร์มเป็นยังไง |

หน้าแรกของมือถือกับ desktop **ตั้งใจให้ไม่เหมือนกัน** — คนละผู้ใช้ คนละคำถาม

## กติกาของโครงการ

ข้อเหล่านี้เขียนไว้เป็นคอมเมนต์ในโค้ดด้วย อย่าแก้โดยไม่คุยกันก่อน

1. **AI ต้องแสดงความมั่นใจและเหตุผลเสมอ** — ห้ามมีคำแนะนำที่กางที่มาไม่ได้ (`src/components/AdviceCard.tsx`)
2. **คนเป็นผู้อนุมัติ** — ระบบไม่สั่งเปิดปั๊ม วาล์ว หรือจ่ายสารใด ๆ เอง
3. **ไม่บอกชื่อสารเคมีหรืออัตราผสมแบบอัตโนมัติ** — ส่งต่อให้นักวิชาการเกษตรแทน
4. **เขียวคือข้อมูล ไม่ใช่สีแบรนด์** — สีแบรนด์คือคราม (`--accent`) และดินลูกรัง (`--laterite`)
   ถ้าเอาเขียวมาทำปุ่ม สัญญาณสุขภาพพืชจะอ่านไม่ออก
5. **ปุ่มหลักไม่ต่ำกว่า 56px** (`--tap-min`) และห้ามปิดการซูมของเบราว์เซอร์

## โครงสร้าง

```
src/
  app/
    layout.tsx              ฟอนต์ + sprite + service worker
    globals.css             design tokens ทั้งระบบ (light/dark)
    (farmer)/               หน้าจอมือถือ ใช้ tab bar ร่วมกัน
    dashboard/              จอเจ้าของฟาร์ม
  components/               UI ที่ใช้ซ้ำ
  lib/
    types.ts                สัญญาข้อมูลกลาง
    data.ts                 ข้อมูลตัวอย่าง 12 แปลง 86 ไร่
    format.ts               บาท / เปอร์เซ็นต์ / วันที่ พ.ศ.
    queue.ts                คิวงานออฟไลน์
public/
  manifest.webmanifest      PWA
  sw.js                     service worker
```

## PWA

- service worker ลงทะเบียนเฉพาะ production — ตอน `npm run dev` จะไม่ทำงาน (ตั้งใจ ไม่งั้นแก้โค้ดแล้วไม่เห็นผล)
- ทดสอบจริงต้อง `npm run build && npm start`
- ปุ่ม "ติดตั้ง" จะโผล่เองเมื่อเบราว์เซอร์ยิง `beforeinstallprompt` (Chrome/Edge บน Android และ desktop)
- iOS Safari ไม่มี event นี้ ผู้ใช้ต้องกด Share → Add to Home Screen เอง

ไอคอนตอนนี้เป็น SVG ซึ่ง Chrome รองรับ แต่ก่อนขึ้น production **ควรเพิ่ม PNG 192/512** เพราะ Android
บางรุ่นและ iOS ยังต้องการ raster

## สิ่งที่ยังไม่ได้ทำ

- ยังไม่มี backend — `src/lib/data.ts` เป็นข้อมูลนิ่ง เปลี่ยนเป็น data layer จริงได้โดยคง type เดิม
- ยังไม่มี auth
- `queue.ts` ใช้ localStorage ซึ่งเก็บไฟล์ภาพจริงไม่ไหว → Phase 3 ย้ายไป IndexedDB + Background Sync
- `/ask` ยังไม่ต่อโมเดล
- ค่าความมั่นใจของ Plant Doctor เป็นค่าสมมติ ต้องมาจากโมเดลที่วัดผลกับชุดข้อมูลพืชไทยจริงก่อนเปิดใช้
